SolidMix team dashboard, approved by Saidul 2026-11-20.
A private dashboard inside the website for the Mould Innovation team to manage GALLERY photos and BLOG posts, with a change history. Public pages keep the same design; only content changes.
Access: secret path /mi-team-dashboard-7q4x/ (noindex, nofollow, not in sitemap, not in robots.txt, not linked anywhere). Real login with email + password per team member (start with 3 accounts, equal rights). Passwords hashed (scrypt, per-user salt). Sessions: random token, stored hashed in Convex, 12-hour expiry, logout deletes it. Login lock: 5 wrong passwords for an email in 15 minutes = locked 15 minutes. EVERY dashboard query/mutation checks the session server-side (requireTeamSession); nothing works without a valid session.
First accounts are created with a one-time protected action that needs the Convex env var DASHBOARD_BOOTSTRAP_SECRET.
Gallery: add (upload jpg/png/webp, max 5 MB, alt text required), replace photo, edit alt text, delete (soft delete, can be restored), reorder. Public gallery shows a uniform grid: equal-size tiles, 4 columns desktop / 2 tablet / 1 mobile, 10px gap, fixed 4:5 tiles, photo cropped to fill (object-cover), lightbox shows the full photo. The current 21 photos are the starting data.
History: every add, edit, replace, reorder, delete and restore is logged with who, when, what, and the before and after values. The dashboard has a History tab (read-only in this phase).
Public pages read content from Convex on the server. If Convex returns nothing or fails, the page falls back to the current hardcoded content, so the site never goes empty. After each dashboard save, only the affected public page is rebuilt (on-demand revalidation), so pages stay static and fast for SEO.
Blog management (posts table, editor, migration of 36 posts, Draft/Publish, Trash) is Build 2.

BUILD 2 - BLOG (approved by Saidul 2026-11-20)
Public blog pages keep the exact same design and output; only content comes from Convex. The 36 existing posts are copied into Convex unchanged (same slug, title, h1, description, excerpt, category, date, time, featuredImage, blocks, canonicalOriginal). If Convex fails or has no posts, pages fall back to the current JSON files.
Body format stays the same block list as today (p, heading, list, image, table; inline **bold** and [text](url) inside text), so FAQ detection and FAQPage JSON-LD keep working.
Dashboard Blog tab: list with search and Published/Draft filter; Trash (N) behind a toggle; New post and Edit with fields Title, URL slug, H1 (defaults to title), Meta description (required, 50-160 characters, live counter), Excerpt (required), Category (existing categories only), Date, Featured image (upload, alt required), Body block editor (add Paragraph, Heading H2/H3, List, Image, Table; move up/down; remove; Bold and Link helper buttons), Preview using the same renderer as the public page, Save draft, Publish, Unpublish, Move to Trash, Restore. Unsaved-changes warning. Drafts and trashed posts are never public.
Slugs: lowercase letters, numbers and hyphens; unique; must not clash with any existing page slug or reserved route. Changing the slug of a published post creates a permanent redirect from the old URL.
Edit conflict: if someone else saved the post after you opened it, saving is refused with a clear message.
New posts appear in the blog index, sitemap, their own page, the appointments teaser if among the latest 3, and at the top of page 1 of their category; legacy category order stays as it is; trashed/unpublished posts disappear everywhere.
SEO: sitemap lastModified = updatedAt (or date for unedited posts); Article JSON-LD gets dateModified; canonical and OG unchanged.
History: every post create, edit, publish, unpublish, slug change, trash and restore is logged with before/after.
UX rules learned from the gallery: visible file picker button + drag & drop + preview; Trash behind a toggle; no full-list reload flicker; per-button busy labels; optimistic trash/restore; errors next to the field; after each save revalidate the affected pages in the background and show "Live on site ✓".
